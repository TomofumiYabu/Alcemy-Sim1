# UI改善レポート — 星灯りの錬金工房

調査日: 2026-10-24 / 対象: `63bfaf0`（調査開始時の `work` ブランチ）

## 結論

**「工房を眺めて育てる喜び」と「次に何をすればよいか即座に分かる操作」を、画面の中心に据えることを推奨する。** 現状は基本ループが成立し、統一した配色と保存保護を備えたMVPである。一方、大手の商用2Dタイトルを目指すには、画面構成、専用アート、状態変化の演出、操作品質を一体で設計し直す必要がある。

最優先は、工房を大きく見せる画面構成と文字・操作サイズの改善。次に、設備・人物・素材のアートを統一し、合成・帰還・販売・研究の手応えを加える。背景画像の差し替えだけでは、現在の長い移動距離や情報の小ささは改善しない。

既存のReactとシミュレーション分離は活用できる。今回の規模でゲームエンジンを全面移行する必要性は認められない。まず既存の一巡だけで商用品質を目指す「縦断サンプル」を作り、品質基準を確定してから全画面へ展開する。

本書は改善提案であり、UI実装・新機能追加・公開は行っていない。対象プラットフォームは現在の仕様に合わせ、デスクトップブラウザーを主軸、スマートフォンを実用的に遊べる副軸と仮定した。

## 3. 推奨アートディレクション

**「夜の青緑に、炉と真鍮の暖かい光が灯る、手描きの錬金工房」** を推奨する。現在の色調を発展させ、暖かい作業空間と冷たい夜景の対比を作品の目印にする。

画面中央は読みやすい2D俯瞰の部屋とする。配置座標は現在の直交6×4を維持し、設備絵にわずかな立体感を持たせる。最初からアイソメトリック座標へ移すと、奥行き順・当たり判定・タッチ対象の調整が増えるため、別途必要性を評価する。

床・壁・窓・作業棚は雰囲気を作る背景、釜と蒸留器は操作対象として分離する。背景の描き込みを抑え、動かせる設備の輪郭と選択枠を最も明瞭にする。配置マスは通常時は薄く、配置モードで明示する。装飾棚を購入設備に見せないことが重要である。

UIの本文背景は読みやすい無地を基本とし、木・紙・真鍮の質感は縁と見出しに限定する。全パネルへ濃い紙テクスチャや装飾を足すと文字の読みやすさが下がる。

| 要素 | 提案仕様の初期値 |
| --- | --- |
| 色 | 夜の背景 `#101C24`、工房の深緑 `#203B35`、本文 `#F2E8D5`、真鍮 `#D8B66E`。実際の組合せはコントラスト検証で確定 |
| 役割色 | 選択・主要行動=金、稼働=青緑、不足=琥珀、危険操作=赤系。色に必ず形・文言を添える |
| 文字 | 本文16pxを基準、重要な補足14px、見出し20〜28px。マップ上に読ませる極小文字を置かない |
| フォント | 読む場所は日本語ゴシック、題字・大見出しは明朝。ライセンス確認済みフォントのサブセット配信を検討 |
| 数字 | 残時間・金貨・個数は等幅数字で揺れを防ぐ |
| 操作サイズ | タッチ操作の主要対象44×44 CSS px以上を設計目標とする。これは本作の品質目標であり、規格の最低値の説明ではない |
| アイコン | 素材6種・設備2種・通貨・機能を同じ線幅、視点、光源で制作。OS依存の記号・絵文字を置換 |

## 4. 画面構成の改善

### デスクトップ

通常のプレイ画面は「常時見える資源」「工房」「選択したものの詳細」「短い通知」を中心にする。在庫・派遣・研究は切替パネルにし、一覧を一度にすべて縦へ積まない。研究画面は広い表示領域を使う。

```text
┌ 星灯りの錬金工房 ─ 金貨 / 知識 / 保存状態 ─ 設定 ┐
├ 次の一歩：イリスを派遣する                 [開く] ┤
├──────────┬─────────────────────┬────────────────┤
│ 工房     │                     │ 選択中の調合釜 │
│ 冒険者   │   生きている工房     │ レシピ・材料   │
│ 在庫販売 │   6×4の配置空間      │ 残時間・不足   │
│ 研究     │                     │ [合成開始]     │
│          │ [設備を置く]         │ 移動 / その他  │
├──────────┴─────────────────────┴────────────────┤
│ 傷薬 +1 / イリス帰還・薬草 +4、清水 +2   [記録] │
└───────────────────────────────────────────────┘
```

これは情報配置の案であり、完成アートではない。1440×900では工房と選択設備の主要操作を同時に表示する。1366×768も受入対象にし、狭い幅では右詳細を下部シートへ切り替える。大きなキャッチコピーや全5段階の説明は初回導入・ヘルプへ移し、プレイ中は「次の一歩」だけをコンパクトに残す。

切替で隠れる派遣の残時間や素材待ち設備数は、常設の小さな要約から把握できるようにする。全画面をタブ化するだけで状況が見えなくなる改修は避ける。

### スマートフォン

上部に金貨・知識と次の目標、中央に選択画面、下部に「工房／冒険者／在庫／研究」の固定ナビゲーションを置く。設備タップで詳細シートを開き、主要ボタンを親指で届く位置へ配置する。端末のセーフエリアとソフトキーボードを考慮する。

工房を画面幅へ無制限に縮小しない。320px幅でもマスの操作領域を確保し、必要なら工房内だけパン・ズームを許す。設備一覧からも同じ操作へ到達できるようにする。文字拡大時は情報量を減らすのではなく、詳細表示へ逃がす。

初回は目標の「開く」で該当パネルを開き、対象ボタンまでフォーカスを案内する。戻る操作で直前の選択とスクロール位置を復元する。

### 工房と設備の詳細

通常時は「稼働中」「素材待ち」「停止中」「仕上げ中」を、設備の姿と状態バッジで区別する。例えば稼働中は炉の灯りと泡、素材待ちは小さな素材アイコン、停止中は消えた炉、仕上げ中は停止予約マーク。停止後も現在のバッチが完成する既存ルールを見た目にも反映する。

設備の選択は輪郭・床の選択枠・詳細見出しの3点を同期する。配置時は候補位置のゴースト、合法/不正の形と色、確定価格を表示する。ドラッグは任意の補助操作とし、既存の「設備を選ぶ→空きマスを選ぶ」を維持する。交換は低頻度なので「管理」へまとめ、開始/停止と同じ強さで常時並べない。

工房全体の「稼働3／素材待ち2」から不足設備へ移動できるようにする。補給と消費のレートは将来有効だが、表示するなら理論最大値と実績値を区別する。素材不足で停止する生産を、常時達成できる生産量として表示しない。

### 冒険者と研究

イリスとローワンは、現状でも固有名と肩書きがあるため、顔・服装・道具の違いを与える効果が大きい。派遣先は森/遺跡の小さな地図カードにし、報酬アイコンと所要時間を併記する。現在の仕様では肩書きによる能力差はないため、絵や文言で未実装の採集ボーナスを示唆しない。

研究「魔力を結ぶ式」は知識・採集・生産をまたぐ3つの前提を持つ。現行の同じ列内の縦線だけでは依存関係を十分に表せない。デスクトップは選択ノードに関係する線だけを強調し、スマートフォンは前提チェックリストと前提ノードへの移動を優先する。9ノードの段階で巨大な自由移動ツリーを作る必要はない。

「合成時間10%短縮」は、実際に計算した「傷薬 8.0秒→7.2秒」と併記する。「蒸留器解放」には設備絵と「薬草からエキスを作れる」を表示する。研究達成後は「蒸留器を配置する」など新しい行動へ案内し、進行中の仕事へは効果が遡及しないことも説明する。

### 演出と音

| きっかけ | 視覚・音の提案 | 制御 |
| --- | --- | --- |
| 選択・押下 | 明確な押下状態、短い柔らかなクリック音 | 視覚反応は次の描画で返す。通信や長い演出待ちを作らない |

| 帰還 | 肖像の状態変化、報酬2種の小通知、短い到着音 | 自動回収は維持。追加の受取クリックを要求しない |

| 研究 | ノードと解放先をつなぐ発光、道具の紹介 | 初回の重要解放だけやや強く。スキップ可能で入力を長く遮らない |

## 6. GPT-Imageの活用方針

今回の課題判定にはコード・実画面の証拠が揃ったため、画像生成は実行していない。**採用候補のアート方向を具体化する次段階では有効**であり、許可された用途として以下を提案する。

| 用途 | 適性 | 制作時の条件 |
| --- | --- | --- |
| 工房のコンセプトアート | 高い | まず1部屋で光源・材質・色を確定。操作対象の輪郭を背景より明瞭にする |
| 人物肖像2名・探索先2景 | 高い | 共通設定と参照絵を使い、服飾・陰影・枠・縮小時の顔の見え方を揃える |
| 設備・素材の原画 | 有効だが調整が必要 | 透過背景、共通視点、同じ接地位置・光源。小サイズでの識別を検証 |
| 完成UI全体の1枚絵 | 方向共有には有効 | 文字・ボタン・数値・ゲージは実装で描画。画像内に焼き込まない |
| 多数のアニメーションコマ | 要検証 | 形状や接地位置の揺れが生じ得る。初期は静止画＋分離した泡・炉光・蒸気で構成 |

初期素材セットは、工房背景1点（背景と前景を分離できる設計）、設備2種、アイテム6種、人物2名、探索先2景を目安とする。汎用機能アイコンはSVGで整え、発光・泡・選択枠はコード側で重ねる。研究9件すべてに専用大判アートを用意するのは後回しにする。

生成指示の例: 「オリジナルの中世ファンタジー錬金工房。夜の青緑と炉の暖色。手描き2D俯瞰、直交6×4の配置が読み取れる床、真鍮と木、左上の共通光源。中央の操作領域は低密度。文字、UI、ロゴ、既存キャラクターを含めない。」

画像は共通アート基準で選別・修整し、書き出し解像度、トリミング、透過境界、容量、接地位置を検証する。採用素材の制作元・利用条件を記録する。細密な1枚絵が生成できても、操作品質や量産時の統一感まで完成したとは判断しない。

## 7. 実装方針と段階的な進め方

### 実装境界

- `App.tsx`: 画面切替、共通HUD、通知、詳細シートの統合。`useGame`は切替でアンマウントせず、進行・保存の接続を一つに保つ。
- `WorkshopPanel.tsx` / `EquipmentDetail.tsx`: 床・設備絵・状態表示と操作詳細を分ける。DOMの意味とキーボード操作を維持する。
- `ExpeditionPanel.tsx` / `InventoryPanel.tsx` / `ResearchTree.tsx`: 肖像、事前結果、前提強調、解放案内を追加する。
- `QuestProgress.tsx`: 既存状態から「今できる具体的行動」を導出する。別の進行フラグを大量にセーブへ追加しない。
- `style.css`: 色・書体・余白・重なり順・アニメーション時間をトークン化し、コンポーネントごとに整理する。
- アート参照はUI側のアセット定義で安定IDに紐づける。Viteのimportまたは`BASE_URL`を使用し、`/Alcemy-Sim1/`配信を維持する。

合成・派遣・販売の計算は既存エンジンを正本とする。演出が必要な場合は構造化した一時イベントをUIへ渡し、表示用ログの日本語を解析して演出の条件にしない。再読込やタブ所有権の引き継ぎで過去の演出を再生しない。

シミュレーションは100ms刻みを維持し、見た目の進捗はCSS等で補間する。アニメーション用に全ゲーム状態を毎フレーム更新しない。24設備規模ならまずDOM/CSSで測定し、多数の描画物による実測の問題が出た時点でCanvas等を検討する。

数量指定販売や「素材を何個残すか」は既存コマンドの仕様を変えるため、UIレイアウト改修とは分けて境界テストを追加する。収納・隣接効果・自動販売・オフライン進行は別のゲーム仕様変更であり、今回のUI完成度の前提にしない。

## 8. 品質の合格基準

以下は未達成の目標を含む受入案であり、今回すべて検証済みという意味ではない。

- 1440×900と1366×768で工房と主要設備操作を同時に見られる。390×844で冒険者・在庫・研究へ1回のナビ操作で到達する。
- 320px幅・200%文字拡大で操作不能や読めない重なりを生じさせない。重要な説明は14px以上、主要タッチ対象は44px以上を目標とする。
- 本文のコントラスト4.5:1以上を基準に確認する。選択・不足・停止を色だけで判別させない。
- キーボードだけで一巡・配置・移動・取消ができる。タブ切替と詳細シートのフォーカス位置が明確である。
- 新規プレイヤー5名程度の形成的テストで、5秒見てゲームの目的と最初の行動を説明できるか、一巡を口頭補助なしに終えられるかを確認する。少人数結果を市場全体の証明とは扱わない。
- 常時表示する進捗は滑らかに見せ、24設備稼働時も入力への視覚反応100ms以内を初期目標に計測する。描画60fpsは代表端末を定めて評価し、現状の達成値とはしない。
- 同時完成や自動再派遣で通知・音が過密にならず、演出軽減とミュートでも結果が理解できる。
- 保存失敗、待機タブ、旧セーブ移行、破損復旧、アート読込失敗でも操作と情報が失われない。
- 画像追加後も通常パスとPagesパスでアセット404がなく、初回転送量と操作可能までの時間を測定して増加を管理する。

今回の調査では既存の一巡を3画面幅で確認した。自動検証の最新実行結果は `PROGRESS.md` の「UI改善調査」を参照する。
