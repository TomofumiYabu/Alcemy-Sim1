# 進捗・引き継ぎ

最終更新: 2026-10-24（Asia/Tokyo）。現在の段階: M1公開済み。追加依頼のサブエージェントレビューを完了（機能変更なし）。

## ユーザー指定Goal

「ゲームとして動作する状態」。冒険者の雇用・派遣→素材回収→設備の配置と自動合成→販売→研究→再読込後の継続を完成させる。開発・検証はCodex Cloud内で行う。

## 実装済み

- 冒険者2名、探索先2か所、出発時の報酬確定、自動帰還回収、研究で解放する自動再派遣。
- 6列×4行の工房、調合釜・蒸留器の購入と配置、無料移動、レシピ割当、素材の自動消費と合成、停止後の仕上げ。
- 素材3種・製品3種、3レシピ。薬草エキスと魔晶片から魔力薬を作る多段階合成。
- 販売と金貨、合成による知識、3系統・計9研究。速度・報酬・知識・売価の改善、設備/探索先/レシピ解放。
- 初回の5段階目標案内、工房の記録、デスクトップとモバイルに対応する日本語UI。
- 100ms固定tick。入力を変更しない状態遷移、安定した処理順、同時設備の材料競合の防止。
- バージョン付きブラウザーセーブ、5秒ごと/操作時/非表示時の保存、残時間を含む復元、破損時の上書き停止、確認付き初期化、保存失敗の表示。
- Zodで構造と参照を検証。研究の前提・一意性、設備の位置/ID、ジョブ/報酬の整合性も確認。

単体テストでは実初期資源から最初の一巡と全9研究への到達、tickの分割結果一致、同時消費、配置・資金不足、途中停止・移動、研究/派遣の開始時条件、複数段階製造、保存破損・容量不足などを検証。

E2Eは6シナリオ: 初期状態から一巡と保存復元、配置拒否と設備競合、破損セーブからの復旧、保存容量不足でもプレイ継続、全研究と蒸留/魔力薬/自動再派遣、非表示時間の停止。Playwrightの時計を進めて検証し、実時計で長く待つことはしない。

公開サイトへChromiumから直接HTTPS接続する追加実行は、CloudのプロキシCAをChromiumが認識できず、12ケースともゲーム読み込み前に `ERR_CERT_AUTHORITY_INVALID` で停止した。ゲーム内のアサーション失敗ではなく、この実行を成功件数には含めない。

その後、既存のNode CA設定と環境プロキシを使うPlaywright APIRequestで公開HTML・JS・CSS等をTLS検証付きで取得し、同じ応答をChromiumへ渡す方式で確認。配信されたMVPの一巡・研究購入・保存復元、ページ例外なし、横溢れなしを両画面幅で確認した。ブラウザー自身の直接HTTPS経路を検証したとは扱わない。証明書検証を無効化する設定、CAや秘密値の複製は行っていない。
