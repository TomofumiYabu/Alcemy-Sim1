# UI改善の納品記録

2026-10-25（Asia/Tokyo）。ユーザー指定Goal「6. 納品」に向けて、公開済みUI-1／UI-2に続くUI-3／UI-4を実装した。対象は [Solへの指示書](SOL-UI-HANDOFF.md) の既存M1機能のUI改善。新しい経済・ゲーム機能は追加していない。

## 実装

- **全機能のアート**：簡潔なローワン、停止状態の蒸留器、魔晶片・薬草エキス・魔力薬、森・遺跡を追加。全13画像を背景・設備・人物・アイテム・探索先に分離し、文字・状態・操作はDOMを使う。設備は進行中のjobだけを点灯させ、停止予約では仕上がるまで点灯する。
- **素材と研究の導線**：不足数と実際の入手先を表示。同じ入手先のボタンはまとめ、森／遺跡への派遣、必要な研究、蒸留器の配置／操作へ移動する。派遣先を選択しても出発はユーザーが決める。研究は前提へのフォーカス、費用・不足数・効果例・解放内容・解放後の操作を表示する。
- **入力と状態**：主要ナビ・研究に自作SVGを使用。満杯時は購入を無効にして交換を案内。配置取消を工房内のEscapeへ広げた。薬草エキスの全量販売には魔力薬の材料でもあることを添えた。
- **設定と音**：OS追従／手動の演出軽減、文字サイズ、通知オン／オフ、音オン／オフと音量を追加。設定はゲーム保存とは別に検証・保存する。音は初期オフで、有効化後の操作から最大1バッチ1音。外部音源や依存追加はない。

GameState、schemaVersion 2、contentVersion履歴、旧v1の移行とバックアップ、Web Locksによる所有タブ、100ms tick、非表示・オフライン時の非加算、開始時条件の仕事、経済・研究数・レシピ数は維持した。

Pages本番ビルド・Cloud Chromium・1366×768・演出ありで、釜12台＋蒸留器12台を継続稼働。各12個の完成後も24台が稼働し、24知識・製品別の通知集約を確認。20回の画面切替ハンドラから次のrequestAnimationFrameまで平均22.8ms、p95 33.2ms、最大46.5ms。ページ例外・console error・リクエスト失敗0。24台の完全同時完成は別のE2Eで1通知への集約を確認済み。

全13画像は430,830 bytes（約421KiB）。この24設備・未雇用fixtureの初回転送はHTML／JS／CSS／読み込まれた画像／faviconで486,896 bytes（約475KiB）、DOMContentLoaded 102.6ms。森画像は雇用後に表示されるためこの測定には含まず、表示時に約67KiB追加される。小さい魔晶片画像はJS内へ埋め込まれる。localhost・冷たいキャッシュでの測定であり、公開回線・全端末・60fpsの達成を示すものではない。

検証したPages成果物はJS `index-BESGceIA.js`、CSS `index-DqDQCbsR.css`。実時間の新規プレイでも雇用→派遣→3回合成→販売→最初の研究を完了し、ページ例外なし。操作動画は `/tmp/alcemy-delivery-demo.webm`（約6.2MiB）。人物比較・各画面・計測JSONは `/tmp/alcemy-delivery-*`、補助スクリプトは無視対象の `.cache/` に保持し、commitしない。

追加単体テストの初回は、既存の秒表記が「8.0秒」であるのに期待値を「8秒」としたため1件失敗した。期待値を正し、最終177件は成功。最初の補助E2E起動はsocket制限で失敗し、正規の追加network権限を用いて成功した。依存宣言・lockfile・保存schema・ゲーム計算の変更はない。
