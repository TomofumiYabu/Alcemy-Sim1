# Alcemy Sim

中世ファンタジーの錬金術工房経営ゲーム。冒険者による素材収集、工房設備による自動合成、研究ツリーによる恒常的な成長を組み合わせます。

1日1ターンの工房・店舗経営ゲームです。冒険者の雇用・派遣、設備の配置・自動合成、陳列品の来客販売、研究9件、ブラウザーへのセーブと復元を実装しています。

このブランチのT1は実装・ローカル検証済みで、mainへのマージ・公開は未実施です。公開URLは引き続きRF完了時のタイマー版です。[T1の納品記録](docs/T1-DELIVERY-2026-10-26.md)で検証・PR・公開状態を確認できます。

## 遊び方

1. 冒険者ギルドで **イリスを雇う → 森へ派遣**。調合釜で **自動合成を開始**。
2. **1日営業する**。森は150作業（1日）で帰還し、傷薬は80作業で完成して倉庫へ入ります。準備中や放置中には進みません。
3. 翌日の **店・在庫** で傷薬を棚へ陳列し、もう1日営業。お客さまが棚から購入します。当日完成品や未陳列の素材は売られず、売れ残りは棚へ残ります。
4. 日報で売上・生産・探索を確認し、金貨と知識で **森の恵み** などを研究。自動再派遣・蒸留器・遺跡・魔力薬へ進みましょう。

工房／冒険者／店・在庫／研究をナビで切り替えます。初回は画面上部の短い目標と「開く」で次の操作へ進めます。PCでは工房の右、モバイルでは設備をタップして詳細を開きます。保存・初期化・ヘルプは上部の「設定」、移動・交換は設備詳細の「移動・管理」にあります。設備は購入ボタンを押してから空きマスを選んで配置でき、移動は無料です。操作結果は保存成功後に確定し、5秒ごとの保存確認も行います。日報の再表示や再読込で日が追加されることはありません。セーブは利用中のブラウザーに保存され、別端末には同期しません。

全マスが埋まった場合も、停止して合成を終えた設備は同じマスで別種類に交換できます。交換先の購入価格が必要で、元の設備の返金はありません。調合釜は最低1台残します。

複数タブでは1つのタブだけが進行・保存し、他は待機します。先のタブを閉じると最新セーブから引き継ぎます。Web Locks対応のブラウザーが必要です。公開済みv1/v2セーブは資産・仕事残量を保ってschema 3へ移行し、初回の保存前に元JSONのバックアップを残します。移行後は棚が空の第1日の準備から始まります。更新前から開いているゲームのタブは一度再読み込みしてください。

工房背景、調合釜・蒸留器、イリス・ローワン、全6アイテム、森・遺跡は専用画像を使用し、完成・帰還・販売・研究を短い通知で表示します。素材が足りないときは入手先や必要な研究へ進めます。設定では動きの軽減、文字サイズ、通知、任意の音と音量を変更でき、ゲームの記録とは別に保存します。音は初期オフです。素材の制作元と使用条件は [基本素材](src/assets/ui2/README.md) と [追加素材](src/assets/delivery/README.md) に記録しています。

## Codex Cloudでの開発

作業ディレクトリは `/workspace/Alcemy-Sim1`。Node.js 24.19.0 / npm 11.9.0 とCloudにあるChromiumを利用します。外部APIキー、DB、Dockerは不要です。

```sh
cd /workspace/Alcemy-Sim1
bash scripts/setup.sh
npm run dev
```

開発サーバーは5173番ポートを使用します。検証は別のシェルで実行できます。

```sh
npm run check
```

Vitest単体テスト83件、型検査、本番ビルド、通常パスとGitHub PagesパスそれぞれでデスクトップとモバイルのChromium E2E（各80件、計160件。単体テストと合わせ243件）を実行します。E2Eは4173番ポートに専用サーバーを起動して終了時に停止します。結果は `test-results/`、失敗時のtraceや画像も同ディレクトリに出力され、Git管理には含まれません。`CHROMIUM_PATH` で既存のブラウザー実行ファイルを指定できます。

[店舗営業の設計](docs/SHOP-SIMULATION-DESIGN-2026-10-26.md)と[性能・表示・配信確認の手順](scripts/README.md)と[リファクタリング対応記録](docs/REFACTOR-RESULTS-2026-10-25.md)も参照してください。
